# 알려진 문제

표준화 전 API 라 브라우저 판올림 한 번에 동작이 바뀐다. 여기에는 이 저장소가 실제로 부딪힌 문제와, 그것을 어떻게 확인했는지를 적는다.

## 스크롤이 생기는 iframe 은 그려지지 않는다

**확인한 버전**: Chrome 151.0.7922.172 (macOS). 151.0.7922.138 에서는 정상이었다.

캔버스 자식으로 둔 `<iframe>` 의 문서가 프레임보다 길어서 **스크롤이 생기면, 그려지는 것은 스크롤바뿐이고 문서 내용이 통째로 빠진다.** `drawElementImage()` 도 `texElementImage2D()` 도 마찬가지다. 예외는 나지 않고 `gl.getError()` 도 0 이다. 그냥 빈 그림이 나온다.

이 회귀 때문에 11번 예제가 검은 화면만 나오는 상태가 됐다.

### 어떻게 확인했나

200×150 iframe 을 캔버스에 그리고 불투명 픽셀을 셌다. 전부 채워지면 30000 이다.

| 자식 문서                                        | iframe 속성      | 불투명 픽셀 |
| ------------------------------------------------ | ---------------- | ----------- |
| 프레임보다 긴 문서                               | 그대로           | 150         |
| 프레임보다 긴 문서                               | `scrolling="no"` | 30000       |
| 프레임보다 긴 문서 (`html { overflow: hidden }`) | 그대로           | 30000       |
| 프레임에 들어가는 문서                           | 그대로           | 30000       |

150픽셀이 무엇인지 보려고 회색 바탕에 그려 PNG 로 떴다. 오른쪽 끝에 세로로 뜬 둥근 막대 하나, 오버레이 스크롤바였다. 글자도 배경도 없었다.

360×480 iframe 두 개를 나란히 둔 11번과 같은 모양에서도 결과는 같았다. 스크롤이 생기는 앞장은 언제나 빈 텍스처, 프레임에 들어가는 뒷장은 언제나 정상. 순서를 바꿔도 결과는 그대로였다.

### 우회 방법

둘 중 하나면 된다.

```html
<iframe src="page.html" width="360" height="480" scrolling="no"></iframe>
```

```css
/* 자식 문서 쪽 */
html {
  overflow: hidden;
}
```

캔버스에 올릴 문서는 어차피 스크롤할 방법이 없다. 프레임 크기에 맞춰 두고 넘치는 부분은 잘라 내는 편이 낫다.

### 소용없었던 것들

원인을 찾는 동안 시도한 것들이다. 전부 효과가 없었다.

- `layoutSubtree` 를 껐다 켜기
- iframe 크기 바꾸기, 노드를 떼었다 붙이기 (떼었다 붙이면 아예 0픽셀이 된다)
- 자식 문서에 노드 추가, 자식 `body`/`html` 배경 변경, 자식 쪽 `requestAnimationFrame` 이후에 그리기
- 캔버스 밖에서 먼저 렌더링한 다음 캔버스 안으로 옮기기
- `--disable-site-isolation-trials`, `--disable-features=IsolateOrigins,site-per-process`
- `src` 대신 `srcdoc` 이나 `document.write()` 로 문서 넣기 — 짧은 문서는 되고 긴 문서는 안 된다. 문서를 넣는 방법과는 상관이 없다
