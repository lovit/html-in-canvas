# 글쓰기 규칙

마크다운 파일, 이슈 본문, PR 본문, 커밋 본문, 코드 주석 모두에 적용된다.

## 1. 하드랩 금지

문단 안에서 줄을 바꾸지 않는다. 문단이 길어도 한 줄로 이어 쓴다.

이유는 두 가지다. 첫째, 단어 하나만 고쳐도 뒤따르는 여러 줄이 함께 밀려 diff 가 실제 변경보다 크게 보인다. 둘째, 줄이 끊기는 위치가 글쓴이 화면 폭에 고정되어 읽는 사람 환경에서는 어색하게 끊긴다.

### 줄바꿈을 써도 되는 곳

줄 자체가 의미를 갖는 곳에서만 쓴다.

- 리스트 항목 (항목 하나가 한 줄)
- 표의 행
- 코드 블록 안
- 인용문
- 제목
- 문단과 문단 사이의 빈 줄

### 나쁜 예

```markdown
이 API 는 아직 표준화 전이라 이름이 바뀔 수 있다. 오래된 글을 그대로 따라 쓰면 undefined 만 만난다.
```

### 좋은 예

```markdown
이 API 는 아직 표준화 전이라 이름이 바뀔 수 있다. 오래된 글을 그대로 따라 쓰면 undefined 만 만난다.
```

### 어떻게 강제되는가

| 대상 | 장치 |
| --- | --- |
| 저장소 안 마크다운 | prettier `proseWrap: "never"` 가 커밋 시 문단을 한 줄로 되돌린다 |
| 저장소 안 마크다운 | prek 훅 `check-hard-wrap` 이 커밋을 막는다 |
| 이슈/PR 본문 | 훅이 닿지 않는다. 본문을 파일에 쓰고 `node scripts/check-hard-wrap.mjs <파일>` 로 확인한 뒤 `--body-file` 로 넘긴다 |

정말 줄바꿈이 필요한 파일에는 `<!-- allow-hard-wrap -->` 를 넣어 예외 처리한다. 거의 쓸 일이 없어야 정상이다.

## 2. 기계가 쓴 것 같은 문장 금지

`/humanize-ko` 스킬의 기준과 같다. 요약하면 이렇다.

- 번역투를 쓰지 않는다: "~에 대한", "~를 통하여", "~되어집니다", "~라고 할 수 있습니다"
- 명사로 만들어 늘리지 않는다: "실행을 수행한다" 대신 "실행한다"
- 근거 없는 수식어를 붙이지 않는다: "혁신적인", "강력한", "매우 중요한"
- 한 문장에 한 가지만 담는다
- 불릿과 이모지를 남발하지 않는다. 이어지는 설명은 문단으로 쓴다
- 단정할 수 없으면 단정하지 않는다. 확인한 것과 추측한 것을 구분해 적는다

## 3. 전문 용어는 원어 그대로

`drawElementImage`, `layoutSubtree`, hit testing, origin trial 처럼 원어가 표준인 말은 번역하지 않는다. 억지 번역은 검색도 안 되고 뜻도 흐려진다. 대응표는 @docs/glossary.md 에 있다.

## 4. 사실과 추측을 구분한다

브라우저에서 직접 확인한 것과 문서에서 읽은 것을 섞어 쓰지 않는다. 스펙과 실제 구현이 다르면 "스펙은 A 인데 Chrome 151 에서는 B 였다" 처럼 확인 시점과 환경을 함께 적는다.
